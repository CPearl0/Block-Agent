# 开发说明

## 项目约定

- 保持根包 `io.github.cpearl0.blockagent`，新增源码放入匹配的标准 Java 源目录。
- `core` 不依赖 Minecraft 类，便于用普通 JVM 测试；`game` 负责客户端线程中的原生操作。
- 模型生成有界 JSON 程序，由本地解释器执行。
- 连续动作通过通用原语、条件和循环组合，不为具体资源或建筑硬编码整套流程。
- 保留两个核心测试文件；增加测试时优先覆盖预算、取消、恢复和实际缺陷。
- 所有 Mixin 保持在 `game.mixin` 的专用包内，避免把普通运行时类放进 Mixin 包。
- 提交前运行 `spotlessApply` 和 `build`。本地 IDE 设置、配置、密钥及游戏数据不得放进仓库。

`gradle.properties` 是模组名称、ID、版本、包组和依赖版本的构建配置来源。资源处理会展开 `META-INF/neoforge.mods.toml` 的占位符。

## 本地开发接口

普通安装不会监听 HTTP 端口。需要自动化验收时，显式给**游戏 JVM**添加参数：

```text
-Dblockagent.bridge.port=3081
```

接口仅绑定 `127.0.0.1`，在游戏实例的 `blockagent/bridge.json` 写入临时地址、令牌与进程号。客户端正常退出后删除描述文件。不要把描述文件或令牌写入日志、文档及 Git。

请求使用 `Authorization: Bearer <令牌>`：

| 请求 | 用途 |
| --- | --- |
| `GET /status` | 读取真实代理状态 |
| `GET /tools` | 读取工具定义 |
| `POST /command` | 以 `{"instruction":"任务"}` 提交任务 |
| `POST /cancel` | 停止任务和开发动作 |
| `POST /tool` | 代理空闲时执行单个原生工具 |

`/tool` 接受 `name`、`args` 和可选 `timeoutMs`，代理忙碌时拒绝执行。强制聊天控制权只属于真实代理任务；直接调用工具不能用于代替聊天接管验收。该接口仅用于开发与验收。

## 验证范围

构建会检查编译、格式、15 项核心测试和模组打包。真实玩法验证应使用独立游戏实例及服务端，单独保存运行证据，不把实例、世界或凭据放进源码仓库。

核验运行结果时使用实际位置、背包、方块和菜单状态。模型总结和工具返回的成功文字不能替代独立结果检查；取消测试中的旧任务被替换也不等于自然完成。
